# 验证结果与边界

日期：2026-10-12、2026-10-18。硬件：MECHREVO P916F-PTL，BIOS 1.01，已提取的 EC 映像版本 01.01.00。验证没有刷写固件或修改 BIOS/SPI 保护。

## 实机端口协议

| 设置 | 风扇 0 RPM | 风扇 1 RPM | 统计 |

| 原始 PWM 128，约 50.196% | 5204 | 5018 | 最后 3 个样本均值 |
| 原始 PWM 192，约 75.294% | 6731 | 6501 | 最后 3 个样本均值 |
| 两路目标 4000 RPM | 3929 | 3985 | 最后 3 个样本均值 |
| 两路目标 6000 RPM | 5961 | 5940 | 最后 3 个样本均值 |

| 独立 RPM 测试后自动控制 | 0 | 0 | 恢复后查询 |

使用者确认风扇有响应。参数变化、握手、RPM 响应和自动恢复相互吻合。没有电气 PWM 波形测量，也没有对 RPM 传感器进行外部仪器标定。

## 插件与 FanControl 282

插件 DLL 经实际 API 调用得到：

| 操作 | 风扇 0 RPM | 风扇 1 RPM |
|---|---:|---:|
| 请求 50%，编码 128 | 5183 | 4968 |
| 请求 75%，编码 191 | 6780 | 6514 |
| 关闭后约 8 秒，恢复自动 | 2501 | 2303 |

测试覆盖 `Initialize -> Load -> Set -> Update -> Reset -> Close`、重复关闭及重新初始化。禁用和关闭各发送了自动恢复命令。最后只读检查两只风扇均为 0 RPM。

FanControl 282 自身的 `PluginBackendProvider` 成功加载三个传感器，验证了完整 RPM 配对标识；FanControl 主程序也记录了成功初始化。公开源码保留了同一份 C# 控制实现，构建/安装脚本已去除个人路径并改为参数。

## 26 项模拟测试与 2 项宿主回归测试

`plugin/test.ps1` 使用假硬件，完全不访问 EC：

1. 只读初始化/采样/关闭不写 EC。
2. PWM 量化、RPM 读数和禁用恢复。
3. 关闭后只恢复一次、重复关闭不重复释放。
4. Set 部分失败后恢复并拒绝后续 PWM。
5. Read 失败后清空读数、恢复并停止后续访问。
6. 只读状态发生错误时不切换 EC 模式。
7. NaN、无穷、负值和大于 100 的百分比在写入前失败。
8. 自动恢复失败会报错并重试。
9. 关闭恢复失败时仍释放硬件句柄。
10. 休眠状态恢复自动并禁止继续访问。
11. 日志异常不能阻止恢复。
12. 0/100% 编码端点正确。
13. 瞬时 RPM 采样不一致保留 PWM、清空过期读数，随后可继续调速。
14. 自动状态的瞬时采样不一致不妨碍后来开启手动控制。
15. 连续 60 次采样不一致仍可控制，日志只记一次并能恢复。
16. 成功采样结束异常状态，后续异常仍可恢复。
17. 采样异常开始和恢复各记一次日志。
18. 转速读取优先使用一致重试，正确选择风扇查询参数。
19. 高字节上升或下降一级时允许 256 RPM 组合歧义。
20. 更大采样歧义丢弃，传输超时仍向上传递。
21. 启动时空闲端口不消费输出，也不额外等待。
22. 持续待取输出先等待 100 毫秒、仅消费一个字节，再检查 20 毫秒空闲。
23. 等待期间被其他读取者取走的输出不再消费。
24. 输入持续忙时有界超时，不读取输出。
25. 同步期间出现输入活动则停止，不消费响应。
26. 消费后输出再次出现则停止，确保不循环清空。

提供 `-FanControlDirectory` 后另测 FanControl 282 的实际 `PluginControlSensor -> Control.Update()` 路径：连续 60 次 RPM 采样失败不影响手动百分比改变；部分写入失败只抛一次、恢复自动，后续 59 次控制循环不重复抛错或写入。以上共 28 项通过，均使用假硬件。

v0.1.0 的实机日志曾在自动状态下一次 RPM 采样不一致后永久锁定会话，后来手动控制每秒重复抛错。v0.1.1 将采样变化与通信故障分开处理。容差仅针对一次分字节读取的歧义，不削平真实 RPM 波动。

v0.1.1 再经实际宿主 `Control.Update()` 控制本机风扇，50% 最后样本为 5284 / 5073 RPM，75% 为 6867 / 6655 RPM。禁用、关闭和重载成功；关闭后约 8 秒为 4501 / 4295 RPM，自动控制时 PWM 读数为空。测试期间没有采样或通信异常，容差与错误注入由上面的模拟测试验证。

v0.1.2 在 2026-10-18 的实际故障状态下验证：退出 FanControl 后，20 次 PM2 状态读数均为 `0x01`。启动同步消费一个待取字节后，连续十次双风扇读数恢复到约 2875–2886 / 2771–2785 RPM。只读测试、关闭重载和真实宿主后端均通过，暴露两个 RPM 传感器及一个共享 PWM；FanControl 主程序重新记录初始化成功，原配置哈希一致。此轮未主动设置 PWM；手动控制路径由假硬件回归验证，50% / 75% 实测数据来自前述 v0.1.1 测试。

第 12 项仅为编码测试，未在实机设置 0% 或 100%。实际休眠唤醒、低速起转/停转、长期高负载、强制结束和第三方并发访问尚未验证。不同 BIOS/EC/驱动版本也未验证。

原始日志可能含个人路径及环境信息，因此公开的是白名单整理后的 [RPM 样本](validation-samples.json) 和本摘要，而非本机日志全量导出。
